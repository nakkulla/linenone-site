Research run by AI agentsAI 에이전트가 수행하는 연구

Researchline · the board I use to run and record research workResearchline · 연구 작업을 진행하고 기록하는 보드

Each task is written down as an issue. AI sessions take issues from a queue and do the work, a model other than the one that wrote a change reviews it, and the server checks the actual pull request before a task counts as done. What was done, why, and who reviewed it stays on the issue.할 일은 이슈로 적어 둡니다. AI 세션이 대기열에서 이슈를 가져가 작업하고, 변경은 그것을 쓴 모델이 아닌 다른 모델이 리뷰합니다. 일이 끝났는지는 서버가 실제 PR을 확인해 정합니다. 무엇을 왜 했는지, 누가 검토했는지도 모두 그 이슈에 남습니다.

At a usage limit사용 한도에 걸리면

한 계정에서 실행이 사용 한도에 닿으면 허용해 둔 다른 내 계정 중 여유가 있는 쪽으로 그 실행만 옮기고, 나머지 작업은 있던 자리에 둡니다. 한도를 우회하지는 않습니다. 옮기지 않고 리셋을 기다리게 할 수도 있으니 위 시뮬레이터에서 두 방식을 바꿔 가며 끝나는 시각을 비교해 보세요.When a run reaches the usage limit on one account, only that run moves to another of your allowed accounts that still has room; everything else stays where it was. No limit is bypassed. You can also have it wait for the reset instead; switch between the two in the simulator above and compare when the night ends.

  1. 창 맞추기.Align the windows. 매일 08, 13, 18, 23시에 계정마다 가장 작은 모델로 한 줄을 보내 5시간 창을 업무 시간에 맞춥니다.At 08, 13, 18 and 23 h each account sends one line to its smallest model, so the 5-hour windows line up with the working day.
  2. 미리 전환.Switch early. 사용률이 기준을 넘으면 허용한 계정 중 여유 있는 곳으로 그 실행만 바꿔 같은 세션을 이어 갑니다.Past the threshold, only that run moves to an allowed account with room, and the same session carries on.
  3. 보류.Hold. 바꿀 계정이 없으면 그 계정을 서버 전체에서 잠시 빼서 다른 저장소의 작업도 같은 한도에 걸리지 않게 합니다.With no account free, that account is set aside server-wide so work in other repositories does not hit the same limit.
  4. 시험 호출.Probe. 리셋 60초 뒤 정말 풀렸는지 시험 호출로 확인합니다. 장애라면 1분, 2분, 4분 간격을 최대 1시간까지 늘립니다.Sixty seconds after the reset a test call checks the limit is really gone. If the service is down it retries after 1, 2, 4 minutes, up to an hour.
  5. 자동 재개.Resume. 멈췄던 세션이 그 자리에서 이어지고 Discord로 회복 알림이 한 번 옵니다.Paused sessions continue where they stopped, and one recovery notice arrives on Discord.

이슈 하나에 사람이 읽는 본문과 기계가 읽는 영수증이 함께 담깁니다. 영수증에는 어느 모델이 어느 커밋을 검토하고 승인했는지 남습니다. 영수증이 없으면 다음 단계로 넘어가지 않습니다.Each issue carries a body people read and receipts machines read. The receipts record which model reviewed and approved which commit, and without them the work does not move to the next step.

Decision records결정 기록

무게 있는 결정은 ADR(결정 기록)로 남깁니다. 결정이 바뀌면 원본을 고치지 않고 새 기록으로 대체합니다. 리뷰어에게 답할 때 근거 문서와 이슈를 바로 찾을 수 있습니다.Weighty decisions are kept as ADRs (decision records). When a decision changes, a new record replaces it instead of the old one being edited. When a reviewer asks, the supporting spec and issue are one click away.
